## 导言：此刻安全，不等于还有路

一个系统此刻满足所有已定义的限制，并不说明它接下来还能继续满足。惯性、资源消耗、控制能力不足或信息错误，都可能使它在表面正常的时候，已经没有可持续的路径。

[复杂系统分析框架](../framework/book/constraints-and-future-options.md)用可生存性（viability）描述这一区别：可生存核是那些"存在一条能持续满足约束的路径"的状态。本文在此基础上进一步追问：

> **即使这样的路径存在，系统里有没有一个主体，拥有足够的信息、权限和时间，把它真正执行出来？**

这个问题把可生存性从"状态空间的性质"，带到了"控制权、信息与时间的分配"。下面的原则都围绕它展开。

## 一、核心问题

<a id="c1"></a>

> **C1　核心问题。** 对每一个需要保护的约束，都要回答：**谁可以对哪个变量行动，依据什么估计，拥有多大权限、多长时延，同时保持当前与下一步的关键约束？**

这个问题有四个要素：

| 要素 | 问的是什么 |
|---|---|
| **变量** | 被调节的是哪个量或哪条轨迹 |
| **主体与权限** | 谁有权对它行动，权限的范围与上限是什么 |
| **信息** | 行动依据的是哪个状态估计，这个估计有多可靠 |
| **时间** | 从发现、决定到动作生效需要多久，约束还剩多少时间 |

缺少任何一个要素，理论上存在的安全路径都可能执行不出来：物理上存在可行的控制，不代表当前有权行动的主体知道该做什么，也不代表他来得及做。

## 二、控制权的结构

### 2.1 五个要分开的对象

<a id="c2"></a>

> **C2　控制权结构。** 分析一个控制回路时，要分开五个对象：

| 对象 | 问题 |
|---|---|
| **受控输出** | 正在被调节的是什么变量或轨迹 |
| **命令来源** | 命令来自计划、选定的目标、直接人工输入，还是另一个功能 |
| **执行者** | 实际推动执行机构的是什么 |
| **模式与转换** | 在什么条件下，上述分配会改变 |
| **状态估计** | 命令及其限制依据的是什么信息 |

由此得到四个常被混淆的区分：

- **选定目标、选定来源、投入执行者，是三件不同的事。** 设定了一个目标值，不等于有执行者正在追踪它。
- **显示的目标，不是正在被调节的证据。** 界面上显示一个目标，不说明执行机构此刻在调节它。
- **指引不是控制。** 给出建议轨迹的功能，自身并不移动系统。
- **显示的界限，未必等于当前条件下的余量。** 限制值是否按扰动、性能、载荷与估计误差动态修正，取决于具体设计；需要核对其计算条件，不能仅凭界面上的数值推断实际剩余余量。

当操作者对这些事件的理解，与系统的实际状态不一致时，就会出现混乱。

### 2.2 物理耦合

在物理上，不同的受控输出往往是耦合的：一个执行机构可以同时影响几个输出，协调控制也可能同时作用于多个变量。因此，"某个输出归谁负责"是**模型中可以识别的责任分配**，而不是说这些输出在物理上相互独立，也不是禁止协调控制。

### 2.3 优先级是受约束的设计选择

<a id="c3"></a>

> **C3　优先级不是普遍定理。** 各类命令来源之间的优先次序，是在特定阶段、特定构型、特定故障条件下作出的设计选择，不存在适用于所有系统、所有阶段的统一排序。可生存性理论描述哪些状态与动作能满足已定义的约束，但"先保证什么、再优化什么"的完整次序，需要明确定义目标、约束与优先级。

<a id="c4"></a>

> **C4　明确当前的绑定约束及其负责人。** 一个可以检查的分析入口是：找出**当前正在限制安全行动集合的那个约束**，并明确由谁负责满足它。

需要注意：几个约束可能同时起作用。一个外部许可、一条路径目标和一个物理限制，不能被简单合并为"离哪条边界最近就保护哪条"，必须分析它们之间的相互作用。这与 [CF Grammar](../framework/methods/cf-grammar.md) 中"绑定约束"的判断方法一致。

<a id="c19"></a>

> **C19　约束责任需要相应的信息条件。** 指定负责人以后，还需检查负责的决策过程能否及时获得判断该约束所需的信息，或明确当前仍无法消除的不确定性。信息可能分散在多个主体或接口中，责任分配需要覆盖必要的整合与更新机制。

这不要求某一个人集中掌握全部信息；分布式协作也可能形成有效判断。需要检查的是，约束判断所依赖的信息能否在行动窗口内形成、传达和使用。信息不足、融合失效或责任接口缺口，是C8第一类失效的候选形态，不能仅由分工存在就断言无人负责。

### 2.4 资源受限时的需求冲突

<a id="c5"></a>

> **C5　资源受限时，两个需求可能不能同时满足。** 当某种总资源（能量、推力、资金、注意力）受限时，对两个变量的任意要求，可能无法同时实现。此时控制必须在它们之间重新分配。

重新分配的规则是需要设计和验证的，不能写成无条件的口诀，例如"永远先保 X"。其他约束可能改变哪些动作是可接受的。

## 三、安全终点：安全停止必须是一个可达且可维持的状态

<a id="c6"></a>

> **C6　安全终点。** 对资源有限的任务，恰当的问题通常不是"能否无限期保持在约束内"，而是"能否在剩余时间和资源内，持续满足约束并**到达一个可接受的终点**"。这更接近捕获盆或有限时域的可达性问题，而不是无限时域的可生存核。

<a id="c7"></a>

> **C7　"安全停止"要对整个相关系统成立。** 一个状态要算作安全终点，必须对**整个相关系统**是可以到达、并且可以维持的，而不只是"执行机构停止了动作"。

几类常见的误判：

- **停下需要过程。** 一个移动的系统要停下，需要足够的距离和时间，并且要防止停下的过程中与其他系统冲突。
- **停下本身可能制造危险。** 停在某些位置，会对其他参与者构成新的风险。
- **关闭不等于结束。** 一些系统在主过程停止后，仍需持续的资源维持安全，例如持续冷却或持续供能。
- **"保持"可能在消耗终点所需的资源。** 一个系统暂时保持当前状态，看起来稳定，却可能正在消耗到达终点所需的资源。把它称为"安全状态"是不完整的，必须把剩余资源、终点的可用性、信息与控制都计算进去。

## 四、三类失效

<a id="c8"></a>

> **C8　三类失效。** 从控制权、信息与约束的角度，可以把失效区分为三类：

| 失效类型 | 含义 | 要问的问题 |
|---|---|---|
| **控制权归属或理解失效** | 没有明确的负责主体，或操作者对"谁在负责"的理解与实际不一致 | 每个受控变量此刻由谁负责？操作者是否正确理解？ |
| **依据无效的估计行动** | 有权行动的主体，依据的是一个已经失效的状态估计 | 这个估计在什么故障假设下才可信？ |
| **联合约束处理不当** | 为保护一个余量而采取的动作，违反了另一个余量 | 各个约束能否在可用权限下同时被满足？ |

这三类是分析范畴，不是完整的因果解释，也可能同时出现。实际的失效过程还会涉及组织、运行与人的因素，超出了这个简化模型。

<a id="c18"></a>

> **C18　联合约束的冲突也需要在规则层面检查。** 针对不同危险分别制定的规则，可能在同一状态下给出不相容的要求。若没有明确的适用范围、优先条件或冲突处理机制，权衡可能被推迟到信息不足、时间紧张的现场。

研究时应比较规则各自的前提、共同适用区域和是否存在联合可行解；不能仅凭方向不同就认定规范矛盾。若引入裁决准则，包括C17提出的候选比较方式，仍需说明价值取舍、可执行条件、新风险与领域验证，不能把某一准则作为所有冲突的通用答案。

这三类失效不限于工程系统。在组织之间的合作、长期关系与国家之间的承诺中，都可以找到同样结构的失效：没有约定谁负责一个共同约束；依据过时的判断行动；保护自己的余量时挤压了对方的余量。

## 五、信息与不确定性

<a id="c9"></a>

> **C9　需要鲁棒保证时，要表示与可信误差界限相容的状态集合，不能只用一个点估计。** 当不同信息源不一致时，合理的做法是扩大"可能的真实状态"的集合；而且要说明，在什么故障假设下，这个集合确实包含真实状态。

<a id="c10"></a>

> **C10　信息源之间的一致，不能证明估计正确。** 几个传感器或信息源相互一致，不足以确立误差的界限。有些错误的估计内部是自洽的，因此不会产生任何可见的矛盾信号。这类**静默失效**需要独立的监测和明确的故障假设。

<a id="c11"></a>

> **C11　异质性需要被证明。** 来自独立物理原理的信息，可以应对某些共同模式的失效；但一个综合推算出来的估计，可能与原始输入共享模型误差或输入误差。"信息来源不同"是一项需要证明的性质，而不是默认成立的。这与[不确定世界中的行动](../framework/book/acting-under-uncertainty.md)中关于共同失效的讨论一致。

<a id="c12"></a>

> **C12　置信度下降时，未必应当减弱干预。** 一个常见的直觉是：对状态越没把握，保护功能的权限就应当越小。这个直觉没有一般的安全保证。置信度下降时，可能需要的恰恰是**更保守的动作**，而不是更弱的干预。更合理的原则是：动作必须对所有与可信误差界限相容的状态都是安全的。

<a id="c17"></a>

> **C17　不确定性下，显式比较可恢复性与未来选择。** 当无法认证一个对所有相容状态都安全的动作时，可以将不同动作对后续可恢复性、有效选择与不可逆后果的影响，作为候选比较准则。比较必须说明模型、情景、时域、约束、成本及评价标准。

这是在C12的保证无法获得时引入的**候选决策原则**，不能由C12单独推出，也不提供安全保证。“更多路径”不自动意味着更好：路径可能共同失效、代价不可承受，或只是分析者遗漏条件的估计。若要比较恢复范围，需要定义所比较的对象与关系，而不是直接数选项。多个动作也可能均不可恢复、无法排序，或缺乏足够证据。

若另采用概率口径，[《平稳不等于有退路》LK1、LK2与LK5](../framework/foundations/lock-in-vs-probability.md#lk5)区分问题发生概率、条件锁定概率及后果，并说明高条件锁定概率不足以单独排除方案。该补充同样需要明确事件、时域、信息与资源条件，不把模型内的恢复保证或上界直接当作现实安全认证。

**原则还需要实现与检验。** 时间受限时，全面比较方案可能不可行。可研究在时间较充裕的阶段，将经验证的判断转化为可识别的触发条件、训练、规划或受限权限，并检验在信息误差、认知负荷与时延下是否仍可使用。是否允许预先排除某些选项，需要验证适用边界、误排后果和替代路径；不能仅凭本原则规定某个动作方向或认定其余选项可恢复。

识别启动决策研究讨论经验、情景识别与心理模拟，并不把快速决策一概解释为没有推理的反射，参见[Klein的原文章节](https://www.theisrm.org/documents/Klein%20%281989%29%20A%20Recognition-Primed%20Decision%20Model%20of%20Rapid%20Decision%20Making.pdf)。这些研究支持检查原则的可用形式，不能替代对某一具体规则的有效性验证。原则能否实施，同样需要信息、表达形式、权限与时间，这与C14的交接条件相呼应。

## 六、一个候选的保护结构：鲁棒过滤

本节描述一个已有数学方法支持的结构，用来说明上述原则怎样落实。它来自控制屏障函数及其对测量误差的鲁棒推广（Ames 等，2017；Cosner 等，2021），不是本文的新定理。

**成立条件。** 以下仅示意连续时间、无输入时延条件下的结构。保持安全集合需要初始状态位于所认证的集合内、模型与可信误差集合覆盖真实演化、控制输入满足执行约束，并存在持续可行且具有所需正则性的闭环控制解。一次优化有解不等于全程保证；本文的目标函数本身也不能替代屏障条件、证明或实现验证。具体假设须按所引用的方法逐项检查。

### 6.1 结构

给定一个安全集合，以及一个可信的状态误差界限。在每一时刻：

1. 列出所有**与当前估计相容的可能真实状态**；
2. 找出那些**对所有这些可能状态都能保持安全**的命令，构成可接受命令集合；
3. 在这个集合中，选择**最接近原始请求**的命令。如果原始请求本身已经在集合中，它就不被改动。

用公式表示，这是一个最小干预问题：

$$
u^{*} = \arg\min_{u \in U_\varepsilon(\hat x)} \lVert u - u_{\text{cmd}} \rVert^{2},
$$

其中 $U_\varepsilon(\hat x)$ 是对误差界限 $\varepsilon$ 内所有状态都满足安全条件的命令集合。在估计与界限固定时，误差界限越大，这个集合不会变大。

它最小化的是"偏离原始请求的程度"，而不是风险、工作负荷或系统性能。

### 6.2 不可行意味着什么

<a id="c13"></a>

> **C13　可接受命令集合为空，只说明这次认证失败，不说明没有安全路径。**

- 它可能来自真实的物理冲突，也可能只来自保守的条件、宽松的误差界限或不充分的模型。
- 它不能指出是哪个假设失败了。
- 它不证明事故不可避免。
- 它也不证明人能做得更好。

### 6.3 交接的前提

<a id="c14"></a>

> **C14　交接不是普遍的安全状态。** 当自动功能无法给出安全命令、把控制交给另一个控制者（例如人）时，需要论证接收方拥有**足以支持有效应对的信息、权限、可行策略或目标，以及足够的反应时间**。这不要求每次都新增权限或更换目标，而是要求交接后确实存在可执行的路径；没有这样的论证，转交责任不能作为安全得到改善的证据。

这一点可按[不完全信任下的合作](./cooperation-under-incomplete-trust.md)与[统一术语](../framework/methods/canonical-vocabulary.md#recovery-time-structure)的计时口径检查：接收方发现后，是否有时间完成理解、判断、协调与实施。最迟开始整个流程与最迟开始实际实施分别记录；不能等到实施的最迟时点才开始理解情况。这里对应的是时间结构，具体安全结论仍需领域验证。

### 6.4 命令路径与旁路

<a id="c15"></a>

> **C15　保证只覆盖经过保护结构的命令路径。** 一项安全保证，只适用于在其假设下真正经过保护结构的命令。手动控制、维护、远程协助、重置与降级模式等路径，都需要单独分析。

旁路是这项保证的缺口，但它的存在本身不证明会出现不安全的命令：另一层独立的联锁、受限的权限或物理上的不变量，也可能使它安全。有用的工作是**列出所有命令路径，并说明每一条由什么证据覆盖**。

## 七、四项保障义务

<a id="c16"></a>

> **C16　四项保障义务。** 要论证一个系统在某一运行阶段是安全的，需要分别提供四类证据：

| 编号 | 义务 | 需要的证据 |
|---|---|---|
| **G1** | **联合可行性** | 有明确的安全集合、可用的权限，以及一个能同时满足相关约束的控制者 |
| **G2** | **信息界限有效** | 在指定的故障与模型假设下，有一个确实包含真实状态的可信集合 |
| **G3** | **及时实现** | 模型与实现考虑了发现、决定、执行、采样与时延 |
| **G4** | **交互被充分建模** | 对扰动、其他参与者与共享资源的假设是站得住的 |

这四项是诊断范畴，不是统计上相互独立的原因。执行时延会降低联合可行性；另一个参与者的行为会使状态预测失效；资源的不确定会同时改变信息界限和控制界限。

## 八、五个比较性质：哪一项义务最难满足

不同领域、同一领域的不同运行阶段，最难满足的保障义务不同。本文提出用五个性质来比较：

| 性质 | 含义 | 要问的问题 |
|---|---|---|
| **时间比 Θ** | 到达边界前可用的时间，相对于发现、决定与纠正所需的时间 | 负责的主体能否及时完成有用的动作？ |
| **恢复要求 F** | 到达并维持一个可接受的恢复状态所需的时间、资源与条件 | 这一阶段及其周边系统，是否存在可恢复的状态？ |
| **可观察性 O** | 限制安全的那些变量能被推断到什么程度，包括故障模式与异质信息 | 不确定性界限是否可信？ |
| **命令时延 τ** | 从决定到动作实际生效的时延 | 决策权应当放在哪里？延迟的效果怎样核实？ |
| **耦合 K** | 对其他参与者、基础设施与共享资源的依赖 | 保证必须覆盖哪些外部行动？ |

<a id="c20"></a>

> **C20　外部过程驱动的危险，需要端到端的时间核对。** 时间余量不能只检查最后行动者。应从同一基准情景与时间坐标出发，记录危险何时可被观测、信息何时形成与传达、何时被用于判断，以及应对何时完成并起效。

计时要区分数据年龄、观测与传递延迟、实施前延迟和实施时长。发现之前的信息形成与传递，不再重复计入发现后的完整应对时长 \(\tau_{\mathrm{response}}\)。串行且边界清楚的阶段才可累加；并行、重叠或流水线阶段应按事件时间戳计算端到端时延，不能机械相加。

若所列链路与方案来不及，应检查瓶颈、替代信息与方案，以及基准轨迹是否遗漏了早期可用信号；不能由总时延单独断定每个主体都没有余量，或直接归责某一环。可比较的研究方向包括观测、传递与应对速度、暴露与缓冲、任务或接口重构等，不限定为只有两种改变。

这些时延与危险演化都需要证据、区间和依赖条件。更早信息若引发不同动作、改变环境反馈或完成期限，应比较更新后的完整轨迹。共用口径见[统一术语](../framework/methods/canonical-vocabulary.md#recovery-time-structure)和[压力测试ST8](../framework/methods/stress-testing.md#st8)；信息链核对本身不构成事故因果识别。

**研究假说：** 这五个性质可以帮助判断，在某一运行阶段，四项保障义务中哪一项最难满足，从而判断哪些安全投入最值得研究。

**限定：**
- 它们不是五个通用的标量。到边界的时间取决于候选轨迹；可观察性取决于动力学与传感器；耦合需要结构化的描述。实际研究需要操作化的定义、不确定性范围与单位。
- 这一假说说的是"一个有用的诊断框架"，不是说所有事故只有一个原因，也不是说五个参数就能决定唯一的最优设计。
- "最小余量"本身，不足以说明哪一项改变最有效。比较改变方案，还需要可恢复性、故障覆盖、新引入的危险与成本的证据。

## 九、方法上的两条纪律

**第一，数学论证与经验假说的地位不同。** 第六节引用的方法，在明确假设与完整条件下提供充分条件保证；本文只概述其结构，不另行给出证明。而"五个性质能帮助选择安全投入"是一个经验性的设计假说，它的成立要靠检验。经验假说不能因为使用了同样的词汇，就继承数学论证的确定性。

**第二，事后拟合不是预测。** 用已经发生的事件说明一个框架，只能说明它可以用来提问，不能说明它能预测。要把框架变成证据，需要：在编码结果之前确定样本、范围与纳入标准；由不知道框架排序的独立分析者编码，并报告一致程度；与合理的基线方法比较；计算暴露量（运行时间、距离、相遇次数），而不只是事件数。这与本框架中"冻结预测"的原则一致。

**这一框架在以下情况下会被削弱：** 独立的分析者无法可靠地使用这些范畴；它的排序不优于合适的基线；重要的风险持续落在模型之外；它建议的改变在计入成本与新风险后，没有改善结果。为检查"重要的风险是否持续落在模型之外"，可以逐案记录主要因素是否落在三类失效与四项保障义务之内，并报告这一覆盖比例及其随时间的变化。分类覆盖率衡量的是分类工具对因素的容纳程度，不自动等于因果解释力或预测能力；编码规则、漏项严重度、独立分析者一致程度与基线比较需要分别报告。

## 十、与已有研究的关系

| 已有研究 | 核心内容 | 本文的使用方式 |
|---|---|---|
| Aubin，可生存性理论 | 受约束动态系统中，从哪些状态出发还存在满足约束的路径 | 第三节的安全终点；全文的基础语言 |
| Ames 等 (2017)，控制屏障函数 | 用屏障函数给出保持安全集合的充分条件，并用二次规划实现最小干预 | 第六节的结构 |

| Degani 与 Heymann (2002)，人机交互的形式验证 | 比较机器的实际行为与用户的心理模型 | 与 C2 中"理解失效"相关的检验方法 |

**本文的贡献主要不在数学方法**，数学方法都是已有的。本文的贡献在于：把控制权、信息与时间放在同一个问题（C1）下；给出三类失效、四项保障义务与五个比较性质，作为跨领域分析的统一范畴；并写明这些范畴在什么条件下成立，在什么条件下会被削弱。它们的增量价值，需要与已有的危险分析与工程方法比较后才能确定。

## 十一、局限

1. **只覆盖了技术与控制层面。** 组织行为、激励设计、法规、维护实践与人的适应，大部分不在模型之内。
2. **连续控制的简化。** 第六节针对的是没有输入时延的连续系统。混合系统、离散的软件状态、采样实现、时延与有策略的参与者，都需要专门的分析，不能简单套用。
3. **难点仍在具体领域。** 联合可行性的认证、可信的误差界限与可行的交接方案，在每个领域都是困难的具体工作，本文只给出了问题的形式。
4. **跨领域迁移需要重新定义。** 把这些原则用于社会系统（组织、关系、国家）时，必须重新定义状态、行动、反馈与不确定性，不能直接搬用物理控制的数学保证。迁移的是分析结构，不是保证。

## 小结

可生存性告诉我们：此刻安全，不等于还有路。本文再往前一步：即使还有路，也要问谁能走、凭什么走、来不来得及走。

把这个问题拆开，就得到本文的几组原则：分清控制权的结构，并让绑定约束的负责人拥有所需的信息（C2—C5、C19）；把安全终点理解为对整个系统可达且可维持的状态（C6、C7）；识别三类失效，包括规则层面的冲突（C8、C18）；正确地表示和对待不确定性，将可恢复性作为有条件的候选比较准则（C9—C12、C17）；知道保护结构的保证在哪里结束（C13—C15）；以及用四项保障义务、五个比较性质和沿信息链计算的时间余量，判断在哪里投入最值得（C16、C20 与第八节）。
