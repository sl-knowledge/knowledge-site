## 一、先区分知识等级与证据类型

| 知识等级 | 使用方式 |
| --- | --- |
| 已有研究（Established） | 说明继承的概念、原始来源与适用条件 |
| 综合架构（Synthesis） | 说明本书如何组织不同方法，不把组成部分据为新发明 |
| 工作性诊断（Working Diagnostic） | 给出操作定义、模型、情景、阈值与局限 |
| 研究问题（Research Question） | 明确尚未解决，以及怎样比较和检验 |

这些标签描述一个主张的地位，不是可信度分数。采用成熟理论的名称，也不自动使具体应用成立。

证据记录另分为：已核实记录（FACT）、他人报告（REPORTED）、推断（INFERENCE）、假说（HYPOTHESIS）和未知（UNKNOWN）。所谓FACT仍应注明来源、范围与核实方式；分类本身不能消除测量和解释错误。

## 二、最小符号表

| 对象 | 本书优先记法 | 含义与限制 |
| --- | --- | --- |
| 当前状态 | \(x_t\) | 与问题相关的系统状态 |
| 环境状态 | \(e_t\) | 当前视为外部的条件 |
| 动作或控制 | \(a_t\)，控制论引用可用\(u_t\) | 同一推导保持一致 |
| 扰动 | \(d_t\) | 在已定义范围内变化的外部输入 |
| 动力学 | \(F\) | 状态转移关系，不再兼指自由或未来集合 |
| 目标与时域 | \(T,H\) | 要回答什么，在多长时间内评价 |
| 原始证据 | \(\mathcal D\)，需标时点时用 \(\mathcal D_t\) | 观察和记录；与环境 \(e_t\) 及表示最迟完成期限的普通 \(D\) 区分 |
| 表示及版本 | \(Z_t,Z_t^{(v)}\) | 当前变量、关系和假说的组织 |
| 候选模型集合 | \(\mathcal M\) | 一个或多个候选模型及机制假说 |
| 情景或不确定性集合 | \(\Sigma\) | 当前明确考虑的未来或扰动条件 |
| 允许状态集合 | \(K\) | 由具体约束定义 |
| 可达集合 | \(\mathcal R_H(x)\) | 给定模型、动作条件与时域下能到达的状态 |
| 可生存核 | \(\operatorname{Viab}_H(K)\) | 给定条件下能够持续满足约束的初始状态集合 |
| 行动策略 | \(\pi\) | 从可用信息到动作的规则或条件政策 |

引用其他领域时，保留来源的符号并显式说明映射；不要求外部研究服从这张表。具体应用可以使用自然语言字段，不必把所有对象强行装进一个字母元组。

## 三、系统、能力、通道与机制

| 术语 | 工作含义 | 易混淆处 |
| --- | --- | --- |
| 系统与环境 | 为当前任务选择的分析范围及外部条件 | 分界是建模选择，不是现实天然给定 |
| 状态 | 当前与后续演化有关的条件 | 观察到的输出未必充分揭示状态 |
| 约束（Constraint） | 限制允许状态、动作或转移的条件 | 不是任何“让事情更难”的因素 |
| 绑定约束（Binding Constraint） | 在当前问题中实际限制可行动作或结果的约束 | 多项约束可以同时起作用 |
| 能力（Capability） | 系统可以较可靠调用的资源、技能或转换能力 | 可靠性仍需证据与条件 |
| 外部通道（Access） | 当前可调用但未完全受自身控制的外部资源或接口 | 通道带来的义务与风险也要记录 |
| 机制假说（Mechanism Hypothesis） | 关于变量如何形成变化的候选解释 | 相关性或叙事不能直接升级为因果机制 |

旧稿的Generator按语境拆成能力、机制、动力学或生产过程。需要保留这个词时，应说明具体含义，不再把它当作解释一切的技术原子。

<a id="四可达性存活性与四种边界"></a>

## 四、可达性、可生存性与四种边界

**术语约定。** 本站优先使用“可生存性（Viability）”“可生存核（Viability kernel）”和“可生存性边界（Viability boundary）”。旧稿中的“存活性”“存活核”“存活性边界”分别作为旧译法保留，对应同一组对象，不引入新的数学定义。可生存性讨论给定条件与时域内是否仍有持续满足约束的策略；当前尚未违反约束，不保证后续仍可持续，也不表示永久安全或零风险。

可达性问能到哪里；可生存性问在约束内能否持续。到达一个状态，不代表到达后还能维持。有限资源任务还需要明确安全终点和到达期限。

普通可生存性考察给定动力学下是否存在满足约束的控制；鲁棒可生存性还需明确允许扰动和非预知策略，即不能借助尚未获得的未来信息。开放世界通常只能给出在当前模型与情景下的估计，不能把它写成真实可生存核已知。

| 边界 | 含义 |
| --- | --- |
| 分析范围（System Scope） | 什么被纳入系统，什么暂视为环境 |
| 约束边界（Constraint Boundary） | 穿越后违反当前定义的允许条件 |
| 可生存性边界（Viability Boundary） | 在指定模型、控制和时域下失去持续路径的边界 |
| 可达前沿（Reachability Frontier） | 当前条件下可达集合的边界 |

讨论“接近边界”时要指明是哪一种。

“自由”保留为自然语言上位词，具体研究拆成可达选择、到达后仍可持续的选择、以及环境改变后重构路径的能力。不能用一个状态数量直接给个人、企业和国家排出通用自由分数。

<a id="path-objects"></a>

### 路径的三个对象

讨论一个主体会怎样选择时，要把三个对象分开记录：

| 对象 | 要问什么 | 常见偏差与限制 |
| --- | --- | --- |
| 模型所估计的实际可行路径 | 在指定约束、情景与时域下，哪些路径有条件成立？ | 实际可行性是所要认识的对象；分析者掌握的仍是可能遗漏条件的估计 |
| 主体知道或相信可行的路径 | 主体掌握哪些信息，怎样理解后果？ | 可能漏掉真实退路，或相信实际不可行的方案 |
| 主体认为可以接受的路径 | 主体按什么目标、价值与风险标准比较？ | 可执行的路径也可能被拒绝；这种判断也可能建立在错误信念上 |

三者不天然一致，也不能默认主体相信可行或认为可接受的路径就是实际可行路径的子集。观察到主体继续留在某项安排中，不能单独证明它没有退路，也不能证明它认同这项安排。比较时，要分别写出**安排之内**与**安排之外**各自还剩哪些路径、各自能维持什么。路径数量不能直接代表选择能力，多条路径可能依赖同一资源而共同失效。

这一划分是分析对象的区分，不是完整的选择行为模型。来源与使用：[《不完全信任下的合作》](../../applications/cooperation-under-incomplete-trust.md)第1.1、6.1节。

## 五、表示、变量层级与充分性

表示是相对于目标、时域和可用证据的压缩。竞争表示是对同一批观察仍然相容、但对未来或机制给出不同解释的候选模型。

| 层级 | 纳入理由 | 后续处理 |
| --- | --- | --- |
| Core：核心 | 当前有证据表明实质影响任务判断 | 进入活动表示与检验 |
| Monitor：监测 | 暂非核心，但可能随条件变化变得重要 | 指定监测条件和升级触发 |
| Archive：归档 | 当前不直接用于推理，仍有追溯价值 | 保存来源与再检索线索 |

“决策充分性”需要说明任务、评价标准、允许误差和资源条件。它不是世界完整性，也不能由当前没有观察到错误推出。

区分性观察（Discriminating Observation）指使候选解释给出不同可检验预期的观察、事件或干预。不必要求每次找到全局信息量最大的观察。压力测试只是其中一种办法，压力增加也可能放大噪声、产生选择偏差或损坏系统。

## 六、失效信号、失效原因与表示脆弱性

失效信号包括持续残差、异常响应、校准恶化和新出现的重要差异。对“表示为什么失去适用性”，本站采用以下共用名称：

| 共用名称 | 旧稿称呼 | 含义与区分 |
| --- | --- | --- |
| 初始设定遗漏（Specification Miss） | 初始表示遗漏 | 关键变量、机制或分析范围原先就与问题有关，但最初未进入表示；新证据可能只是揭示旧错误 |
| 结构漂移（Structural Drift） | 名称保留 | 原先可能适用的关系、规则或约束后来发生改变；需区分现实何时变化与分析者何时发现 |
| 任务错配（Task Mismatch） | 任务不匹配 | 表示被用于不同的目标、时域或评价问题；表示可能仍适合原任务，不能仅由错用认定其本身无效 |

这些是表示失效原因的工作分类，不要求互斥或穷尽；多种原因可以并存，也可以暂时无法判断。旧稿称呼作为别名保留，不另建新类别。刚发现一个过去已经存在的条件，不表示现实结构刚刚发生变化；归因需要能区分这些情况的证据。

策略脆弱性研究哪些情景使行动策略失去预定表现；表示脆弱性是本书的工作定义，研究哪些世界条件或任务变化使表示失去充分性。前者与后者应分别记录。

原稿用集合语言表达这些对象；公开稿优先要求实际写出触发条件、观察指标、竞争解释与处置规则，而不把尚未测量的集合当成已知实体。

## 七、最小修订及其层级

| 层级 | 候选操作 |
| --- | --- |
| L0 | 更新参数 |
| L1 | 调整变量权重或作用强度 |
| L2 | 修订机制关系 |
| L3 | 增加、删除、拆分或合并变量 |
| L4 | 改变分析范围、制度情景或约束条件 |
| L5 | 重建表示 |

这是一张比较改动的操作表，不是必须逐级尝试的算法。若已知结构错误，直接重建可能更合适。修订应在复杂度、成本、恢复效果和独立检验之间比较。

## 八、三个需要条件说明的诊断量

### 适应时间余量

本版把比较口径统一为**有效余量**：从当前参考时刻算起，扣除完成整套应对所需的时间后，还剩多少时间。完整应对包括发现后的判断、协调、启动与实施；发现之前的延迟不再计入该时长。

\[
\widehat m_\tau=\widehat m_{\mathrm{eff}}
=\widehat\tau_{\mathrm{survive}}-\widehat\tau_{\mathrm{response}}.
\]

两项时长必须从同一参考时刻计算。本文沿用 \(m_\tau\) 作为有效余量的兼容记法；旧稿的 \(\tau_{\mathrm{adapt}}\) 必须先说明包含哪些阶段，再映射到本版，不直接作为新的统一时长名称。正余量不保证成功，估计还需区间、依赖条件和方案有效性。

<a id="recovery-time-structure"></a>

### 恢复窗口的时间结构

**工作性诊断及其适用设定。** 固定情景、约束、时域和已知可执行的方案集合。以下简化模型假定：期限和各阶段时长固定；完成前不能缓解损失；方案完成后确实能维持所要求的约束。所有时长非负。现实分析使用估计，下面先用无帽符号说明理想化记账关系。

时间线为：不利变化开始 \(t_0\) → 发现 \(t_D\) → 开始实际实施 \(t_A\) → 完成并起效 \(t_C\)。对某一指定方案：

| 记号 | 共用名称 | 含义 |
| --- | --- | --- |
| \(D\) | 最迟完成期限 | 未完成有效应对时维持关键约束的最迟期限；模型约定截至此时完成有效方案仍可避免越界 |
| \(\ell\) | 实施前延迟 | 从开始应对流程到实际实施的判断、协调与启动时间；下式假定发现后立即开始该流程，不另增加可选等待 |
| \(\tau_{\mathrm{exec}}\) | 实施时长 | 从实际实施开始到完成并起效的时间 |
| \(\tau_{\mathrm{response}}=\ell+\tau_{\mathrm{exec}}\) | 完整应对时长 | 发现后所需的判断、协调、启动和实施，总共多久 |
| \(t_L=D-\tau_{\mathrm{exec}}\) | 最迟开始实际实施的时点 | 只扣实施时长，不能当作还可以开始讨论或协调的时点 |
| \(t_R=D-\tau_{\mathrm{response}}\) | 最迟开始整个应对流程的时点 | 需为实施前延迟和实施都留出时间 |

\[
t_C=t_D+\ell+\tau_{\mathrm{exec}},\qquad
m_{\mathrm{eff}}=D-t_D-\tau_{\mathrm{response}}
=t_R-t_D=t_L-t_D-\ell.
\]

因此，\(t_L-t_D\) 是**发现后到最迟开始实施的窗口**，还要容纳 \(\ell\)；只有 \(\ell=0\) 时，它才等于有效余量。若发现后另等待 \(w\) 才开始流程，完成时点再加 \(w\)，实际余量再减 \(w\)。同一段时间不能在完整应对时长和额外延迟中重复计算。

从发现时刻算起，\(\tau_{\mathrm{survive}}=D-t_D\)，所以前后两种有效余量公式对应。若参考时刻不同，或应对已经进入某个阶段，必须改用同一时刻的剩余支撑时间和剩余应对时长。

**恰好赶上与错过期限不同。** \(m_{\mathrm{eff}}=0\) 表示在该确定性模型中恰好于 \(D\) 完成，没有容错余量。超过 \(t_R\) 仍未开始整个流程，或超过 \(t_L\) 仍未开始实施，指定方案才会来不及；不能由此断言未知或新增方案也不可行。

比较多个方案时，要逐方案记录 \(\ell(o)\) 与 \(\tau_{\mathrm{exec}}(o)\)。在共同期限 \(D\) 下，令 \(\tau_{\mathrm{response}}^*=\min_o[\ell(o)+\tau_{\mathrm{exec}}(o)]\)，对应 \(t_R^*=D-\tau_{\mathrm{response}}^*\)。实施最快的方案不一定是完整应对最快的方案。没有有效可执行方案时，不把空集写成有意义的正余量。

### 一个含协调延迟的计时例子

虚构设定：\(D=12\)周，\(t_D=3\)周，\(\ell=1\)周，\(\tau_{\mathrm{exec}}=4\)周。则完整应对需5周，最迟开始整个流程为第7周，最迟开始实施为第8周。第3周立即开始流程，第4周实施，第8周完成；有效余量为4周。发现后到最迟实施的5周窗口包含1周协调，不能把5周全当作额外机动时间。

### 与预警间隔及旧记法的关系

对固定、尚未启动的基准流程，可按完整应对最快的方案设 \(t_V=t_R^*-\delta\)，其中 \(\delta\ge0\) 是事先选定的时间安全阈值，\(t_F\) 是表面表现越过失效阈值的时点。此时 \(m_{\mathrm{eff}}^*\ge\delta\) 等价于 \(t_D\le t_V\)。旧稿的 \(t_V=t_L-\delta\) 在对应方案 \(\ell=0\) 时与此一致；一般情况下不能忽略实施前延迟。\(t_F\) 与这些最迟启动时点没有普遍先后顺序。

发现延迟为 \(t_D-t_0\)，预警间隔为 \(G_W=t_F-t_V\)，有效余量为 \(m_{\mathrm{eff}}\)，三者分别记录。在基准轨迹、流程时长和阈值不变时，单纯更早取得信息改变 \(t_D\)，不改变该基准 \(G_W\)；若监测导致行动或反应改变，需重新估计轨迹。

方案分阶段起效、时长随启动时点变化、判断与实施重叠，或不同方案有不同期限时，需要比较完整轨迹，不能直接套用上述串行加法。一般可恢复性仍需检查完整的动力学与可行策略。

出处与旧案例：[《不完全信任下的合作》](../../applications/cooperation-under-incomplete-trust.md)第二节；检查方法见[《压力测试》ST8](./stress-testing.md#st8)。

### 外部通道依赖型可生存性（Borrowed Viability）

比较允许外部通道与仅靠已定义内部能力时，哪些状态或路径可持续。需要保持可比较的模型条件，记录外部通道是否新增债务、依赖或风险；不能默认两个可行集合必然具有包含关系。

### 预警间隔（Warning Gap）

\[
\widehat G_W=\widehat t_F-\widehat t_V.
\]

这里分别是表面表现越过失效阈值的估计时点，以及恢复能力进入预设危险区的估计时点。结果依赖模型、情景与阈值。实际是否来得及，应另用发现时点、完整应对时长与完成期限计算有效余量，不能直接从预警间隔机械扣除发现延迟。

## 九、决策政策相关词汇

| 术语 | 本书用法 |
| --- | --- |
| 稳健性（Robustness） | 面对一组已说明的可信情景，避免表现过度依赖狭窄假设；不等于任何世界都成功 |
| 避免终止性损失（No-Ruin） | 单独处理可能破坏持续学习、履约和行动能力的失效方式；不是零损失保证 |
| 选择权（Optionality） | 不确定性未解决时保留条件行动的价值；选择更多也可能增加成本 |
| 可逆性（Reversibility） | 按可撤回、撤回代价高、事实上不可逆区分，并说明资源和时间 |
| 承诺（Commitment） | 在共同评价条件下比较现在承诺与最佳可行等待政策 |
| 被迫锁定（Forced Lock-In） | 缺少可持续替代路径；与主动集中资源不同 |
| 渐进锁定（Gradual Lock-In） | 替代路径在一连串局部调整中逐步缩小的过程；不要求某一步明确决定放弃退路，需沿阶段检查，见[ST7](./stress-testing.md#st7) |
| 期限（Deadline） | 超期后资源、义务或行动条件发生变化的时间条件；影响通过具体后果与依赖关系传导，不能只按主体是否重视期限判断 |
| 适应性政策（Adaptive Policy） | 初始动作、事前观察条件、条件动作和退出或修订规则 |
| 路标（Signpost） | 能触发政策更新的事前指定可观察条件 |
| 延迟约束反馈 | 约束表现被缓冲或延迟，不表示约束永久消失 |
| 元控制（Meta-Control） | 在具体决策语境中改变后续约束、接口或行动空间的能力 |

等待的价值若已包含未来信息和条件选择，就不能再把同一项选择权重复加一次。比较行动还需统一费用、风险、折现和可行性条件。

接近失效时的高方差行动，不直接证明人的心理风险偏好发生变化。应先描述目标、可用动作和后果结构，再讨论是否需要心理解释。

获益路径多样性（Outcome Path Diversity）看概率、收益与依赖；致命失效暴露（Fatal Mode Exposure）看严重度、共同原因、不可逆性和概率。多写几条相关故事，不会产生真正独立的获益路径。

<a id="working-mechanism-hypotheses"></a>

### 工作性诊断与机制假说

这里区分概念名称与附着在概念上的经验主张。收入术语表只是便于查阅，不表示相关机制已获验证。

| 项目 | 工作含义 | 知识地位与检验要求 |
| --- | --- | --- |
| 能力与外部通道的非等价 | 当前能提供相同功能，不等于通道撤去后仍可持续 | 条件性的比较诊断；分别核对控制、持续性、切换时间、义务与共同失效，不能默认内部能力总是更优 |
| 余量不足时的路径转移 | 若主体不能接受失去某项关键条件，又相信高风险路径仍能保住它，可能转向高方差路径 | 待检验的机制假说；需测量信念、后果与评价规则，并比较竞争解释，不能由压力或负余量单独推断行为 |
| 默认承担者 | 在特定安排中，未被明确分配或补偿的缺口实际落到的参与者 | 工作性称谓；谁承担何种缺口须有证据。“这些参与者更可能破坏安排”是另一个待检验主张，不能由称谓直接推出 |

来源：[《不完全信任下的合作》](../../applications/cooperation-under-incomplete-trust.md)第6.1、8、10.2、11节。关于这些机制的领域映射、因果解释与预测，仍需独立证据。

## 十、人机研究系统词汇

| 对象 | 含义 |
| --- | --- |
| 研究治理者（Research Governor） | 人负责目标、价值、风险、承诺、停止与修订决策 |
| 表示与证据引擎 | AI协助检索、组织、竞争解释、反证和修订提议 |
| 研究状态（Research State） | 目标、表示、证据、假说、预测、脆弱性、修订日志和待办 |
| 知识状态 | 已知、相信、假设、未知、已否定；均需与证据记录连接 |
| 长期存储 | 可追溯保存的资料与版本 |
| 候选上下文 | 根据当前目标检索得到、尚待验证的信息 |
| 工作上下文 | 经验证与筛选，实际进入当前推理的有限信息 |

“已否定”应记录针对哪个版本和条件；“相信”不能被系统自动改写为“已知”。记忆价值涉及当前相关性、以后复用、遗漏后果与占用成本，不等于语义相似度。

理论迁移依次检查关系结构、因果条件、预测和决策是否保留。类比只生成候选推论，不能生成目标域事实。

## 十一、投资应用词汇

公司系统研究经营转换、资本生产率和每股价值；市场系统研究预期、持仓、订单与流动性；投资者系统研究资金、规模、义务和可持续执行条件。三者相互作用，但不能压成一个质量评分。

财务报表“输出日志”是一种研究提示：还要追踪形成结果的机制。它不否认报表中的估计、未来义务与会计判断。公司增长、总利润增长、每股利润增长和内在价值增长需要分别分析。

新增资本回报率的差分近似需要考虑资本形成、会计口径和时滞。边际购买力、叙事阶段和市场生命周期都是待操作化的表示，不作为价格预测的乘法定律。组合可生存性则关注资金与流动性冲击下能否继续履约和调整，不等同于低波动。

具体说明与金融概念来源见[投资的三个系统](../book/investment-three-systems.md)。
