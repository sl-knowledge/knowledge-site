## 导言：让长期研究形成可追溯的状态

复杂课题往往持续数月甚至数年。新的材料不断出现，旧解释可能失效，目标与时间视野也可能变化。如果每次交流都只留下新的总结，研究很容易忘记哪些是事实、哪些仍是假说，以及结论究竟为什么改变。

本文提出一种人机协作研究系统：围绕当前问题维护结构化研究状态，让证据、竞争解释、冻结的预测、结果与修订相互关联。人负责目标、价值取舍与研究治理，AI协助资料核验、表示构造、反例搜索和版本记录。

它的最终目标包括人的能力变化：能否把复杂材料压缩为少数可理解、可检验的规则，在新问题中提出更好的问题，并逐步形成知道自身边界的判断直觉。保存更多资料只是其中一个环节。

## 阅读前的几个定义

| 术语 | 本文中的意思 |
| --- | --- |
| 表示（Representation） | 针对当前问题保留的变量、关系、机制假说、约束与未知，而非现实本身 |
| 目标／时间视野（Target/Horizon） | 要解释、预测或决定什么，以及多长时间内的结果有关 |
| 决策充分性 | 在声明的目标、证据和风险条件下，当前表示暂时足以支持判断；仍可能需要修订 |
| 研究状态 | 当前判断、依据、未知、竞争解释和待验证预测的结构化记录 |
| 最小修订 | 定位失效原因后，先作足以恢复适用性的必要改动，而非无条件扩张模型 |

后文所列模块属于设计建议。“已核实”“相信”“假说”等状态均应带来源、范围与更新时间，不能将其视为永不改变的真理等级。相关的系统语言可参见[约束、可行性与未来选择](./constraints-and-future-options.md)。

## 第1章　聊天记录与研究状态

一次性聊天的基本结构是：

```text
问题 → 回答.
```

但长期研究更接近：

```text
问题_0 → Z_0 → 证据_1 → 预测_1 → 结果_1 → 修订_1 → Z_1 → …
```

真正应该持久保存的不是所有对话文本，而是：

```text
研究状态 t
```

一个最小研究状态至少包括：

- 目标／时间视野；
- 表示状态；
- 证据状态；
- 假说集合；
- 预测状态；
- 脆弱性状态；
- 修订日志；
- 研究待办队列。

这几个对象和聊天记录的性质完全不同。聊天记录记录“我们曾经说过什么”；研究状态记录“我们当前相信什么、凭什么相信、还有哪些竞争解释、什么结果会证明它错、它从上一版本发生了什么变化”。

这一区分解决了长期 AI 协作中的一个根本问题：对话可以不断变长，但研究状态不应该随对话长度线性膨胀。一个成熟系统应该能够把上百次交流压缩成一个相对小而结构化的当前状态，同时保留历史版本以供审计。

因此，未来不同聊天窗口更适合理解为同一个研究状态的不同 **视图**。用户在哪个窗口提问不应该决定知识本身存在于哪里；真正持续的是问题表示、证据、预测和修订。

## 第2章　工作上下文与记忆筛选

长期记忆不是越多越好。有限注意力下，上下文越大，相关信息越可能被不相关历史淹没；不同目标／时间视野的旧问题表示也可能互相污染。

真正需要解决的是：

```text
当前应该激活哪些记忆？
```

因此，研究系统不应把记忆库整体塞进工作上下文，而应经过：

```text
记忆 → 检索 → 有效性核查 → 筛选 → 工作上下文
```

### 检索

根据当前：

- 目标；
- 时间视野；
- 当前问题表示；
- 当前环境；

检索候选记忆。

### 有效性核查

候选记忆进入上下文前，必须检查：

- 它是否仍然有效？
- 是否已经被后续证据推翻？
- 是否属于当前目标／时间视野？
- 是否只是过去某个假说，而不是事实？

### 筛选

即使相关，也不一定值得占用当前注意力。真正应该进入工作上下文的信息，应优先满足：

- 当前相关性高；
- 遗漏后果重要；
- 复用价值高；
- 上下文占用可控。

因此，记忆价值不等于语义相似性。一个文字上很相似的旧讨论，可能属于完全不同时间视野；一个语义上不相似的旧决定，例如两个月前冻结的目标，却可能决定当前分析是否会问题界定错误。

`记忆价值` 在本文中只作为 **“工作性设计原则”**：

```text
记忆价值 = f( 当前相关性, 未来复用价值, 遗漏后果, 上下文占用 ).
```

它不是成熟认知科学定律，而是研究系统的设计启发。

## 第3章　显式知识状态

如果长期研究只保留“当前总结”，AI 很容易把自己以前的推断重新读成事实。为避免这种污染，研究系统必须把知识拆成多个显式状态。

至少需要：

```text
已核实
```

```text
当前相信
```

```text
待验证假说
```

```text
未知
```

```text
已被反证
```

这五类与输入证据的分类相互配合，但不完全相同。`事实 / 转述 / 推断 / 假说 / 未知` 描述输入证据的认识论类型；知识状态描述一个研究对象在长期系统中的当前状态。

例如：

- 某客户已经正式公告采购，可以是已核实；
- 我们认为其未来会继续扩大采购，是当前相信；
- “采购扩张主要由某项产品性能优势驱动”可能是待验证假说；
- 是否已进入下一代认证仍是未知；
- 某个曾经合理但被后续事实否定的机制进入已被反证。

研究系统还应维护至少四类显式状态：

### 表示状态

当前 \(Z_t\)：核心变量／监测变量、约束、能力、机制假说、不确定因素。

### 证据状态

证据来源、时间、类型、置信度，以及它支持或反对哪些问题表示要素。

### 假说状态

持续存在的竞争表示，不因一次讨论结束而消失。

### 预测状态

已经冻结的概率预测、反证条件与结果状态。

这种结构让知识变化成为真正的：

```text
状态变化
```

而不是每次重新写一篇更长的自然语言总结。

## 第4章　版本、差异与认识过程审计

问题表示会改变，但旧版本不应该被覆盖。

如果今天的 \(Z_t\) 与三个月后的 \(Z_{t+1}\) 不同，研究系统必须保留两件事：

第一，当时为什么那样想？

第二，后来到底什么证据让它改变？

因此，重要问题表示应版本化：

```text
Z^{(1)}, Z^{(2)}, Z^{(3)},…
```

而真正有研究价值的不是长篇新总结，而是：

```text
Diff(Z_t,Z_{t+1})
```

至少包括：

- 新增：新增了什么变量？
- 删除：删除了什么变量？
- 重要性调整：什么重要性变化？
- 机制变化：哪个机制假说被替换？
- 系统范围变化：系统范围是否变化？
- 目标／时间视野变化：是不是其实换了问题？

每次修订还应该记录原因：

- 新增事实；
- 参数更新；
- 初始设定遗漏；
- 结构漂移；
- 任务错配；
- 新的目标；
- 置信度变化。

其中，初始设定遗漏、结构漂移与任务错配对应[统一术语](../methods/canonical-vocabulary.md)的表示失效原因；新增事实、参数更新等仍按记录用途保留。重要条件原本存在但被漏掉，与条件后来改变，应分别记录；原因可以并存或暂时未知。

这形成 **认识过程审计轨迹**。它的价值在于抵抗事后偏差。结果发生以后，人和 AI 都很容易觉得“我们早就知道”；只有旧版本被保留下来，才能区分真正的提前判断和事后重写。

因此，一个成熟研究系统不应该只回答：

> 我们现在怎么想？

还应该能够回答：

> 我们什么时候开始这样想？为什么改变？当时还认为哪些替代解释可能成立？

## 第5章　人负责研究治理，AI协助表示与证据工作

人机协作需要明确角色。这里把负责目标、价值取舍与研究停止条件的人称为“研究治理者”；它与改变未来行动空间的“元控制能力”是不同概念：

```text
人=研究治理者
```

人主要负责：

- 定义和修正目标；
- 决定时间视野；
- 提供价值取舍与可接受风险；
- 决定什么时候承诺；
- 决定什么时候研究足够；
- 对 AI 的问题界定提出质疑；
- 最终承担治理责任。

AI 更适合承担：

```text
AI=表示与证据工作引擎
```

包括：

- 证据检索；
- 候选变量提取；
- 证据分类；
- 竞争表示生成；
- 参照类别检索；
- 机制比较；
- 理论检索；
- 反事实构造；
- 区分性观察设计；
- 预测记录；
- 矛盾检查；
- 失效监测；
- 修订提案。

这种分工不是因为某些任务“人类永远做得更好”，而是因为研究目标本身来自行动者的目的。AI 可以帮助优化一个目标，却不能在没有治理层的情况下自动决定什么目标值得追求、什么不可逆风险可以接受。

在这一分工中，人治理研究目标，AI协助构造、检验和修订问题表示。

## 第6章　主动寻找矛盾，持续维护竞争解释

研究中需要防范一种风险：人和模型沿着当前叙事继续解释新材料，却没有充分检查竞争解释。这可能加重确认偏误。

因此，研究系统必须把 **矛盾检索** 设计成主动功能，而不是等待用户提醒。

每当一个重要问题表示形成后，系统至少应该问：

1. 哪些事实当前解释得最差？
2. 哪个替代问题表示仍然与主要证据兼容？
3. 哪个被忽略变量如果存在，会让当前结论反转？
4. 哪个未来观察最能让竞争模型分叉？
5. 有没有证据被当前叙事方便地降权，却没有充分理由？

同时，竞争表示不能只在一轮分析里出现，之后就消失。长期系统应维护：

\[
\boxed{
\mathcal Z_t
=
\{Z_1,Z_2,\ldots,Z_n\}
}
\]

以及每个候选的：

- 当前支持证据；
- 尚未取得的区分证据；
- 预期观察；
- 退出竞争集合的条件；
- 最后更新时间。

只有真正区分性证据出现以后，某个假说才应该退出当前候选集合。

这意味着研究系统的目标不是永远保持“多元观点”，而是防止 premature closure。一个已经被反复证伪的假说继续保留，同样会浪费注意力。持续维护的竞争模型需要的是**受证据约束的竞争**，不是无限争论。

## 第7章　研究队列、停止规则与资源分配

复杂研究最容易无限扩张。每发现一个相邻理论，都可以再读；每出现一个不确定性，都可以再查；每一个模型都能再细化。如果没有停止规则，“研究更多”会逐渐变成不愿承诺的另一种形式。

因此研究系统需要显式 **研究待办队列**，但研究待办不是简单待办清单。它必须按与决策的相关性排序。

一个问题是否进入当前研究队列，可以用一个非常粗的原则判断：

```text
新增信息预期带来的决策价值 > 研究成本
```

这里的研究成本包括：

- 时间；
- 注意力；
- 计算资源；
- 上下文占用；
- 行动窗口的机会成本。

一个不确定性即使学术上很有趣，如果无论答案如何都不会改变当前问题表示或 decision，就不应阻塞行动。

同样需要 **停止规则**。当以下条件大体满足时，应考虑停止继续研究并进入行动：

1. 当前问题表示已达到决策充分性(\(T,H\))；
2. 剩余未知不太可能改变行动策略；
3. 新信息的预期价值已很低；
4. 行动窗口正在缩小；
5. 继续研究本身开始造成机会损失。

上下文预算因此也是一种真实资源。人与 AI 都有注意力、记忆、计算资源和时间约束。高质量研究系统的目标不是“知道尽可能多”，而是把有限认知资源分配给最可能改变后果的未解决问题。

## 第8章　领域接口与理论检索

通用研究系统不能取代领域知识。一个投资问题需要会计、资本配置与市场微观结构；生命科学需要分子、细胞、演化和实验方法；机器人需要控制、感知和动力学。把这些专业语言全部压成 `约束／能力／可生存性`，只会丢掉真正有用的信息。

因此需要 **领域接口**。

领域接口的作用不是把领域领域对象体系重写成通用语言，而是建立接口：

```text
领域证据 ↔ 通用表示对象
```

它负责告诉研究系统：

- 哪些领域专有变量值得成为状态变量；
- 哪些证据在该领域被视为强证据；
- 哪些机制已有成熟理论；
- 哪些阈值与失效条件有领域含义。

完成目标问题表示以后，AI 还可以进行 **理论检索**。核心问题不是“这像什么”，而是：

> 哪个成熟理论真正研究了当前问题表示中的这种机制？

标准链条是：

```text
目标问题的表示 → 理论检索 → 关系保留检验 → 目标领域证据
```

关系保留检验至少包括：

- 结构保留；
- 因果关系保留；
- 预测关系保留；
- 决策意义保留。

结构映射、causal 推断、可生存性理论、RDM、RL、统计、优化等都应作为推理模块被调用，而不是被重新命名成新的总理论。

这里必须保留一个纪律：

\[
\boxed{
AnalogyGeneratesHypotheses,\ NotEvidence
}
\]

跨领域相似结构可以告诉我们下一步去找什么，但不能替代目标-domain verification。

## 第9章　表示失效监测与最小修订

当表示遗漏关键因素、现实机制发生变化，或研究目标已经改变时，原有表示可能不再足以支持判断。“最小修订”要求先定位问题，再用必要的改动恢复适用性。这里关注的是：**一个长期系统怎样持续监测并处理这些变化？**

研究系统应维护一个表示脆弱性监测。它监控的不是“有没有坏消息”，而是当前 \(Z_t\) 是否出现失去决策充分性的迹象。

典型信号包括：

- 预测误差持续呈现未解释的结构；
- 概率校准恶化；
- 原来稳定的关系被打破；
- 过去不重要的变量开始成为实际约束；
- 区分性事件出现意外响应；
- 机制在特定环境状态下失效；
- 目标／时间视野已经变化但问题表示未切换。

这些信号出现后，系统首先要诊断失效条件：

```text
初始表示是否遗漏？
```

```text
是否发生结构漂移？
```

```text
任务是否已经改变？
```

而不是自动重建全部模型。

接下来调用 **最小修订流程**。按从小到大的修订层级：

- **L0：参数更新。** 在原有表示内更新数值。
- **L1：权重调整。** 改变已有因素的重要性。
- **L2：机制修订。** 替换或调整因果机制假说。
- **L3：变量调整。** 增删、拆分或合并变量。
- **L4：范围与约束修订。** 调整系统范围、适用状态或约束。
- **L5：重建表示。** 原有结构无法充分支持当前问题时重新构造。

研究系统应记录每次修订的触发证据或事件、修订层级、解释力改善、预测改善与复杂度成本。这样一段时间以后，我们不只拥有对世界的研究数据，还会拥有：

```text
关于表示如何失效的记录
```

这些记录可以支持对“怎样发现表示失效、怎样修订”进行经验检验。

## 第10章　如何验证系统是否有效

一个研究系统看起来再完整，也不能靠结构优雅证明自己有效。它必须和更简单基线方案比较。

验证至少需要回答：

- 是否更快找到与决策有关的变量？
- 是否减少遗漏实际绑定的变量？
- 是否提高样本外预测质量？
- 是否更早发现问题表示失效？
- 是否以更小修订恢复充分性？
- 是否减少无关上下文干扰？
- 是否真正改善决策结果？

这需要三类验证。

### 10.1 前瞻研究

从现在开始冻结：

- 问题表示；
- 竞争表示；
- 预测；
- 概率；
- 反证条件；
- 决策规则。

未来真实发生后，再评分与修订。

这是最接近真实研究的方法，因为结果在记录时尚未发生。

### 10.2 合成环境

构造实验者知道真实隐藏状态、机制、约束、环境机制变化的环境，只给智能体部分观察。测试它能否：

- 找到与决策有关的变量；
- 忽略无关细节；
- 发现隐藏的约束；
- 检测结构漂移；
- 用 minimal 修订恢复。

合成环境的价值是真实状态与机制可知，可以检验表示发现与表示修订，而不是只看语言是否有说服力。

### 10.3 历史与回溯案例

历史案例仍然有价值，但对于 LLM 存在训练污染：

```text
提示中隐藏结果 ≠ 模型事先不知道结果
```

因此历史案例更适合机制发现、表示练习与错误分类，不应被当作唯一独立预测验证。

---

### 10.4 评测不只看预测准确率

问题表示评测至少应同时看：

#### 表示效率
多少当前激活的模型复杂度换来多少决策价值？

#### 预测质量
概率预测是否改善？

#### 失效发现
问题表示失效是否更早被发现？

#### 修订效率
是否用更小结构改动恢复？

#### 决策效用
最终行动策略是否改善？

#### 记忆与上下文效率
是否减少 irrelevant 检索与干扰？

真正的目标可以概括成：

```text
MoreDecisionValue PerUnitOfRepresentationComplexity
```

---

### 10.5 认识过程治理比自主性更重要

一个智能体即使能够自动搜索、总结、推理、行动，如果缺少：

- explicit 目标；
- 证据分类；
- 竞争表示；
- 冻结的预测；
- audit trail；
- 停止规则；
- 修订 discipline；

它可能只是更快地产生 self-consistent stories。

因此，人机协作研究系统最重要的能力不只是自主性，而是：

```text
认识过程治理
```

它要求系统知道：

- 什么是事实，什么是假设；
- 什么已经改变，为什么改变；
- 哪些错误属于参数，哪些属于问题表示；
- 什么证据应该让行动策略改变；
- 什么情况下应该停止继续研究；
- 谁负责最终目标与价值判断。

## 附录A：最小数据结构

一个长期课题至少维护以下对象：

### 1. 目标卡
当前目标／时间视野 / 关键决策。

### 2. 表示状态
核心变量／监测变量、约束、能力、机制假说、不确定因素。

### 3. 证据账本
来源、时间戳、证据 type、置信度、受影响的表示元素。

### 4. 假说集合
Persistent 竞争表示与 discriminators。

### 5. 预测账本
冻结的预测、概率、结果、评分。

### 6. 脆弱性状态
策略脆弱性 + 问题表示 vulnerability 信号。

### 7. 修订日志
版本差异、失效分类、修订层级。

### 8. 研究待办队列
当前未解决但暂不阻塞 decision 的问题。

### 9. 停止规则
何时停止继续研究并行动。

### 10. 上下文策略
什么信息进入当前工作上下文，什么只留在记忆库。

## 附录B：术语索引

**研究状态**<br>
长期研究当前的结构化知识状态，而不是聊天全文。

**记忆库**<br>
持久保存的历史信息。

**工作上下文**<br>
当前推理实际激活的有限信息。

**记忆筛选**<br>
对候选记忆进行相关性、有效性与后果筛选。

**表示状态**<br>
当前 \(Z_t\) 及其核心变量／监测变量、约束、机制假说等。

**证据状态**<br>
当前可追溯证据与其 epistemic typing。

**假说集合**<br>
仍在竞争的 representations / 机制。

**预测状态**<br>
被冻结、等待结果的预测集合。

**认识过程审计轨迹**<br>
记录过去问题表示、证据、理由与修订原因的版本历史。

**研究治理者**<br>
负责目标、时间视野、价值取舍、risk、承诺和 stop rule 的治理层。

**表示与证据工作引擎**<br>
AI 在证据检索、问题表示 construction、testing 和修订提案中的主要角色。

**矛盾检索**<br>
主动寻找当前问题表示解释不好的事实与强替代模型。

**研究待办队列**<br>
尚未解决但按与决策的相关性排序的问题集合。

**停止规则**<br>
研究达到决策充分性或继续研究价值过低时的停止条件。

**领域接口**<br>
连接领域词汇与证据规则与通用问题表示 workflow 的接口。

**理论检索**<br>
在目标问题表示已形成后寻找成熟来源 theories。

**表示脆弱性监测**<br>
持续监测当前问题表示是否出现失去决策充分性的信号。

**最小修订流程**<br>
按最低必要层级修改问题表示的运行机制。

**认识过程治理**<br>
对证据、问题表示、预测、修订和研究停止的长期治理纪律。

## 小结

全文留下六个工作原则。

第一，聊天历史不等于研究状态；长期协作需要维护结构化状态，而不是无限堆积聊天文本。

第二，记忆不应整体进入上下文。真正重要的是相对于当前目标／时间视野动态检索、有效性核查和筛选。

第三，证据、问题表示、假说、预测和未知必须分开保存，旧版本不能被覆盖。

第四，人的角色是研究治理者，AI 更适合做表示与证据工作引擎；两者共同维护一个长期闭环。

第五，研究系统必须主动寻找 contradiction、持久维护竞争模型，并用失效信号驱动最小修订，而不是不断给旧故事打补丁。

第六，一个真正有价值的研究系统最终必须通过 prospective、synthetic 和其他可审计评测证明：它比普通对话系统更会找到重要差异、更早发现自己错了，并以更小代价完成修正。

## 附录C：一条证据如何改变研究状态

**以下是虚构的流程示例，用于演示记录方式，没有声称发生过真实实验。** 假设研究目标是判断某套英语练习能否帮助学习者在四周后、更换情境时减少过去时遗漏。

| 研究对象 | 初始版本 v0.1 | 新观察与候选修订 v0.2 |
| --- | --- | --- |
| 问题与期限 | 四周后，在未练过的表达任务中观察时态遗漏 | 保持相同任务定义，避免中途换题 |
| 主要解释 | 规则知识不足是主要瓶颈 | 学习者能解释规则，但限时开口时仍遗漏，开始比较“知道但调用不及时”的解释 |
| 竞争解释 | 题目不熟悉、词汇或表达负担也可能影响表现 | 设计规则提示、熟悉题与新情境的对照，而非只增加语法讲解 |
| 证据状态 | 教师印象属于转述；练习记录有时间戳 | 将具体记录与来源保存，区分观察与原因推断 |
| 事前预测 | 规则训练后应在新情境中减少遗漏 | 在实施新训练前记录预期、期限、比较方法和反证条件 |
| 版本差异 | 初始问题表示 | 若对照支持，修订瓶颈假说并增加“限时调用”变量；若不支持，继续检查其他解释 |

这个过程不要求每次对话都重新填写整套表格。后台需要保存的是：当时的问题、当时能取得的证据、曾作出的预测，以及后来改变判断的理由。人的学习效果和系统整理效果也要分开评价。

## 相关研究与效果边界

检索、记忆、反思与反馈已有相关研究基础，本文将它们组织为长期研究的治理流程：

- [Lewis等，2020：检索-Augmented 生成](https://arxiv.org/abs/2005.11401)讨论外部检索与语言模型的结合，可作为证据检索模块的背景。
- [Park等，2023：Generative Agents](https://arxiv.org/abs/2304.03442)包含记忆、反思与检索的代理架构，是长期状态设计的相关工作。
- [Shinn等，2023：Reflexion](https://arxiv.org/abs/2303.11366)研究利用语言反馈和经验记忆调整后续尝试，与反馈记录和修订有关。

这些研究不能直接证明本文整套流程有效。验证应比较普通对话、仅检索、加入显式状态、再加入预测与修订等版本，在相近资料、时间和计算预算下观察其增量效果。还应记录人的独立提问、解释边界与跨任务迁移是否改善。
