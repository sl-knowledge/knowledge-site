**大语言模型入门系列 · 教师版 v0.2**

配套：[学习者版 v0.2](./lesson-01-representation.md)

教学设计参照：[SL 语言学习试教站](https://github.com/sl-knowledge/lesson0-site)、[《框架驱动的学习循环》](https://sl-knowledge.github.io/knowledge-site/learning/framework-driven-learning)与[《认知失衡：问题从哪里来》](https://sl-knowledge.github.io/knowledge-site/learning/cognitive-disequilibrium)。本课为工作性教学设计，不报告教学实验结果。

## 1. 本课的任务与知识边界

核心任务是帮助零 AI 背景的学习者形成 **Representation（表示）** 的概念，并理解对象、表示规则、目标任务三者的关系。

学习者已有知识：日常编号、照片、颜色与动物种类、数字的相等比较。不假设已知向量、矩阵、分词、机器学习或 Transformer。

预期交付：学习者能自主设计一套数字表示，解释它保留了什么，利用共同约定解读它，并在任务变化时判断是否需要修改。向量、Token ID、Embedding 仅在篇末完成概念与正式名称的交接；不讲点积、注意力、训练过程或上下文计算。

## 2. 设计主线：从已有经验到自主设计

| 学习环节 | 读者此时已有的知识 | 当前任务及其来源 | 教学设计的作用 |
|---|---|---|---|
| 一、运动员号码与照片编号 | 数字可以区分对象 | 用编号指出照片 | 激活生活经验；区分识别对象与了解性质 |
| 二、远程传递照片信息 | 编号能指代事物，但任意编号本身不告诉人颜色 | 朋友看不到照片，只能按共同约定读数字；新目标是获知颜色和种类 | 给出真实、具体的设计约束，让学生自行选择表示，不预设两个格子 |
| 二、检验 | 学生已提出一种方案 | 读出颜色、种类，并编码未出现的黑狗 | 检验信息是否可恢复、规则是否能复用，不只是数字有无变化 |
| 三、自主探索 | 已有可用的数字表示与检验经验 | 给出另一只白猫；问题由学生自己选择 | 逐步移交问题生成权；如无不足，允许保持原方案 |
| 四、概念凝聚 | 已经体验不同表示的用途 | 总结所完成的工作 | 先形成概念，再引入 Representation、Vector 等名称 |
| 五、事实对照 | 已区分编号与表达内容的数字 | 学习真实模型怎样把词元映射为向量 | 提供无法从游戏唯一推导的工程事实，避免反向填充 |
| 六、下一课接口 | 已有表示及检验框架 | 自己提出可继续探索的问题 | 观察独立提问能力；教师只在此后提供下一课的研究主题 |

核心因果链：**任务改变 → 原表示的能力需要重新检验 → 如有缺口则修改表示 → 用新材料验证。** 预测成功同样是推进学习的起点。编号加共享码表、十位与个位编码、两个数字格子等均可能是合理方案；只要符合游戏约束，就不要求学生改成标准答案。

## 3. 教师怎样提供帮助：分级提示

学习者版为自主阅读材料，仅提供一个可选的轻提示和折叠参考方案。教师面对面教学时可按以下等级逐步提供支撑；每级只在前一级无法继续时使用。

| 等级 | 示例 |
|---|---|
| 0：观察 | 留出思考时间，记录学生原始方案与理由；不提示卡片应有几个格子。 |
| 1：明确目标 | “朋友收到数字之后，要能知道哪两件事？” |
| 2：提供最小线索 | “你能先用数字告诉朋友颜色吗？” |
| 3：缩小搜索空间 | “如果一种颜色的写法已经确定，你能再用一个数字记录种类吗？” |
| 4：示范 | 示范白猫的一种编码，让学生自行处理其余照片；若仍不能完成，再演示读取规则。 |

**停止条件：** 学生能够提出有依据的方案，或者能够自行设计下一步检验时，停止增加提示。即使学生答案不同，也先检验其方案，不直接纠正为教师方案。若学生用单个编号配共享的颜色/种类码表，只要无需照片并符合事先约定的规则，也有效；不以题目措辞排斥可行方案。

交接顺序：学生自己的符号或数字 → 检验其功能 → 对照参考编码 → 认识正式名称。参考编码是为了共同讨论而提供的约定，不代表真实嵌入必须具有相同结构。

第三节原则上不提示新问题是什么。教师只需记录学生是否主动发现新需求，或是否选择了原表示仍能完成的任务。若问题由教师示范，不计作学生自主生成的问题。

## 4. 核心概念与形式关系

| 概念 | 专业解释 |
|---|---|
| Object / Domain | 被表示的对象及其定义域。本课可取具体照片，而不是把照片、动物个体和词语混为一类。 |
| Property | 在定义域上可区分的性质，如照片中动物的颜色。 |
| Target | 表示所要支持的任务，如判断颜色是否相同。 |
| Representation | 依据约定建立对象、性质或关系与另一形式之间的对应。本课采用确定性映射作为最小工作模型，并非一切表示的充分定义。 |
| Vector | 本课使用实数向量空间 $\mathbb R^d$ 中的元素，以有序数值坐标表达。 |
| Embedding | 在语言模型语境中，从离散词元到连续向量空间的参数化映射；此处不使用拓扑学的嵌入定义。 |

设 $X$ 是照片集合，$R$ 是编码空间，$f:X\to R$ 是编码规则，$g:X\to Y$ 是目标任务所要求的正确结果。问：能否只根据编码恢复目标结果？

在有限的确定性教学模型中，存在解码规则 $h:R\to Y$ 使得

$$
 g=h\circ f
$$

当且仅当任意 $x,x'\in X$ 满足 $f(x)=f(x')$ 时，也满足 $g(x)=g(x')$（假设 $Y$ 非空）。证明：必要性由相同输入得到相同输出；充分性可在 $f(X)$ 上定义 $h(f(x))=g(x)$，条件保证定义无歧义，其余点任意延拓。

该判据回答的是给定表示是否保留任务所需信息，不保证解码容易、成本低，或学习系统能够找到解码规则。对任意唯一编号，若附带完整对应表，解码可能存在；第一节说的局限，是**不给对应表和其他信息时，编号的数值本身不提供颜色语义**，不是否定编号编码的能力。

参考卡片 $f(x)=(c(x),s(x))$ 中，颜色和种类分别由两个坐标读出。不同照片若颜色与种类一致，就可能具有相同表示。因此它对颜色和种类查询充分，但对识别每张照片未必充分。

本课只建立表示与任务的关系。还没有理由断言向量的加法、距离或点积能够刻画有意义的关系；下一课应先明确要比较什么以及如何检验，再研究运算。

## 5. 真实模型机制的对照与限定

典型的 decoder-only Transformer（如 Llama）采用离散词元编号和可训练的嵌入表。设词汇表大小 $N$，模型隐藏维度 $d$，嵌入矩阵 $E\in\mathbb R^{N\times d}$，则编号 $i$ 的初始词元嵌入为

$$
x_i=E[i,:].
$$

这是查表，而不是将编号的十进制数字本身当作语义特征。分词由实际 tokenizer 决定，一个汉字不必等于一个词元。同一词元编号的初始查表结果相同；后续位置处理与上下文计算另行讨论。模型训练通常会更新嵌入参数，但本课不解释训练过程，也不宣称每个坐标有独立可读的语义。

| 卡片游戏 | 典型语言模型 | 对应边界 |
|---|---|---|
| 照片编号 | Token ID | 都是识别用的编号；对象类型不同 |
| 有约定的数字卡片 | Token embedding | 都是数字表示；卡片是手工显式特征，嵌入通常为学习得到的分布式表示 |
| 按约定读卡 | 后续计算利用向量 | 只说明表示需要被使用；不能推出实际网络的计算规则 |

这里的对应是概念桥接，不是 Transformer 的历史推导，不是用真实模型参数做的实验。本课不要求读者猜出分词器或嵌入表等工程事实。

技术资料：[Hugging Face Transformers — Llama 模型文档](https://huggingface.co/docs/transformers/model_doc/llama)（input_ids、inputs_embeds 与内部嵌入查表）；Vaswani et al. (2017), [Attention Is All You Need](https://arxiv.org/abs/1706.03762)，§3.4 Embeddings and Softmax。

## 6. 评价：学生是否获得可复用的理解？

课后给出不同于课堂的情境：三个水果，要求只用数字传递颜色和是否带籽。不给出格子数和编码规则。让学生设计方案、写一个新水果的编码，并说明接收者怎样读出结果。再改变目标，例如要区分两个颜色和带籽情况都一样的水果，观察是否能判断现有表示的局限。

| 评价维度 | 观察证据 |
|---|---|
| 独立设计 | 能建立编码及共同解释规则，而不是复制两个格子 |
| 可检验性 | 能用新材料编码、解码，并指出成功或失败的原因 |
| 目标敏感性 | 能根据任务决定保留什么，不盲目增加格子 |
| 自主提问 | 能提出新问题及可执行的检验；分别记录教师提供的问题 |
| 提示依赖 | 记录最高提示等级、学生独立完成的步骤，不把参考方案或教师代做计作学生能力 |

记录模板：学生原始方案｜自主问题｜预测/实际结果｜是否修正及理由｜提示等级｜新任务表现。条件允许时，可在一段时间后用新材料复测。这里只给出候选观察方法，不预设教学效果。

## 7. 逻辑链审计与下一课接口

- 任务与约束是否先于表示设计？是：远程传递颜色与种类的任务明确后才要求编码。
- 是否为了引出现有 AI 机制而强行制造失败？否：有效的编号及共享规则可以保留；允许学生成功预测。
- 是否有隐藏知识？数字含义由通信双方事先约定。照片的性质由人提供，本课不处理从图像自动识别性质的问题。
- 检验是否针对目标？是：检验解码结果与照片性质是否一致，而非仅检验数字有无变化。
- 是否提前给出专业答案？正文先探索，参考方案折叠，正式术语集中于篇末。
- 是否交还问题控制权？第三节由学生选问题；第六节先记录自主问题，再给下一课主题。独立阅读时是否真的自主操作，尚无法确认。
- 真实性边界是否清楚？卡片与真实嵌入仅作结构对照，不把手工特征编码当作真实参数或实际训练机制。

**下一课输入：** 对象、表示规则、任务、可检验的性质保留条件。**开放问题：** 已有数字表示时，怎样设计能反映任务所关心关系的比较方法？不能直接假设数字距离就等于语义相似度。
